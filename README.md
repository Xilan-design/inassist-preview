# Сайт ИнАссист — inassist.by

Статический сайт ООО «ИнАссист»: 11 страниц и страница 404. Базы данных и CMS нет. На хостинге
нужны только файлы сайта и PHP для отправки заявок из форм.

Дизайн и вёрстка: [.Xilan.](https://www.behance.net/xilandesign)

---

## Запуск на хостинге

1. **Загрузите сайт.** Распакуйте `inassist-site.zip` в корневую папку домена на хостинге
   (обычно `public_html` или `www`). Внутри уже всё, что нужно: страницы, стили, скрипты, шрифты, картинки,
   `send.php`, `.htaccess`, `robots.txt`, `sitemap.xml`, иконки. Файл `.htaccess` начинается с точки —
   проверьте, что он тоже загрузился (в некоторых файловых менеджерах скрытые файлы не видны).
2. **Настройте приём заявок.** Откройте `send.php` и заполните настройки в начале файла:
   - `$MAIL_TO` — почта, куда приходят заявки (сейчас `info@inassist.by`);
   - `$MAIL_FROM` — адрес отправителя на домене сайта, например `no-reply@inassist.by`;
   - по желанию `$TELEGRAM_BOT_TOKEN` и `$TELEGRAM_CHAT_ID` — тогда заявки будут приходить ещё и в Telegram.
     Бота создают в [@BotFather](https://t.me/BotFather), id чата можно узнать у [@userinfobot](https://t.me/userinfobot).
3. **Включите HTTPS.** Когда на домене заработает SSL-сертификат, откройте `.htaccess` и уберите `#`
   в четырёх строках блока «HTTPS и адрес без www». После этого все адреса будут вести на `https://inassist.by`.
4. **Проверьте форму.** Отправьте тестовую заявку из формы внизу любой страницы и из окна «Связаться с нами».
   Если письмо не пришло, попросите хостинг включить отправку почты из PHP (функция `mail()`)
   или подключите Telegram: он работает без почтового сервера.
5. **Сообщите поисковикам.** Добавьте сайт в [Яндекс Вебмастер](https://webmaster.yandex.ru)
   и [Google Search Console](https://search.google.com/search-console) и укажите карту сайта
   `https://inassist.by/sitemap.xml`.

Требования к хостингу: PHP 7.4 или новее с расширением mbstring (есть почти везде). Для Apache все настройки
уже в `.htaccess`. Для nginx — см. раздел «Если хостинг на nginx» ниже.

## Как устроен проект

```
src/                 ← здесь правят страницы
  *.html             страницы сайта
  partials/          общие блоки: шапка, подвал с окном заявки, форма «Обсудим вашу задачу», соцсети и т.д.
assets/
  css/style.css      все стили (здесь правят); style.min.css — сжатая копия, её делает сборка
  js/*.js            скрипты (здесь правят); *.min.js — сжатые копии
  fonts/             шрифты Manrope (заголовки) и Inter (текст), только кириллица и латиница
  img/               логотип, иконки, картинка для превью ссылок, сертификаты
*.html (в корне)     ГОТОВЫЕ страницы — результат сборки, вручную не править: перезапишутся
send.php             приём заявок из форм
.htaccess            настройки Apache: страница 404, сжатие, кэш, HTTPS
build.js             сборка
tools/               служебное: иконки, снимки страниц для проверки
```

### Сборка

Нужен [Node.js](https://nodejs.org) 18 или новее. Один раз в папке проекта:

```
npm install
```

Дальше:

| Команда | Что делает |
|---|---|
| `npm run build` | Собирает страницы из `src/` в корень, сжимает стили и скрипты, обновляет `sitemap.xml` и `robots.txt` |
| `npm run watch` | То же, но пересобирает сама при каждом сохранении файла |
| `npm run dist` | Собирает и складывает в `dist/` только то, что нужно на хостинге, плюс архив `inassist-site.zip` |

Сборка сама добавляет в каждую страницу иконки, адрес для поисковиков (canonical) и превью для мессенджеров
(Open Graph): их текст берётся из `<title>` и `<meta name="description">` страницы. Адрес сайта —
константа `SITE_URL` в начале `build.js`.

Чтобы посмотреть сайт у себя, запустите в папке проекта любой простой сервер, например
`python -m http.server 8765`, и откройте `http://127.0.0.1:8765`. Формы на локальном сервере и на
GitHub Pages работают в режиме показа: сразу пишут «Заявка отправлена» и ничего не отправляют.

### Общие блоки

Шапка, подвал, форма и другие повторяющиеся части лежат в `src/partials/` и вставляются в страницы строкой:

```html
<!-- @include header active="services.html" -->   шапка; active — какой пункт меню подсветить
<!-- @include contact topic="Реклама" -->          форма; topic — какой вариант выбран заранее
<!-- @include footer -->                           подвал, окно «Связаться с нами», плашка cookie
```

Поменяли блок — он меняется на всех страницах после сборки.

### Новая страница

Скопируйте похожую страницу в `src/` (например, `src/services.html`), поменяйте `<title>`, description
и содержимое, соберите. Страница сама попадёт в `sitemap.xml`. Пункт меню, если нужен, добавляется
в `src/partials/header.html`.

### Стили

Цвета, шрифты, размеры и отступы заданы переменными в начале `assets/css/style.css`
(`--ink`, `--accent`, `--bg`, `--fs-h2`, `--gutter` и т.д.). Ниже файл идёт по блокам сайта в том же порядке,
что и на страницах. Правила для планшета (до 1080 px) и телефона (до 760 px) лежат сразу под своим блоком.

Фирменная деталь — срез под 23° у кнопок и параллелограммы (`--slant`). Иллюстрации нарисованы
в изометрии под тем же углом прямо в разметке (SVG), их анимация описана в разделе «Иллюстрации» стилей.

### Иконки и превью ссылок

`favicon.ico`, `assets/img/favicon.svg`, `apple-touch-icon.png` и `og-image.png` (картинка, которую показывают
мессенджеры и соцсети при отправке ссылки) делаются из логотипа командой `npm run icons`
(нужен запущенный локальный сервер и Google Chrome). Готовую картинку `og-image.png` 1200×630 можно и просто
заменить своей.

### Проверка, что правка ничего не сломала

`node tools/shots.js папка` снимает все страницы на компьютере, планшете и двух телефонах, а также открытое
меню, окно заявки и сборку здания на «О нас». `node tools/shots.js --diff до после` сравнивает два набора
снимков попиксельно и сохраняет отличия. Путь к Chrome задан в начале `tools/shots.js`.

## Если хостинг на nginx

`.htaccess` там не работает. Аналог для блока `server`:

```nginx
error_page 404 /404.html;
charset utf-8;
gzip on;
gzip_types text/css application/javascript image/svg+xml application/json application/xml text/plain;

location ~* \.(css|js|woff2)$ { expires 1y; }
location ~* \.(png|svg|ico)$  { expires 1M; }
location ~ \.php$ { include fastcgi_params; fastcgi_pass unix:/run/php/php-fpm.sock;
                    fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name; }
```

Путь к `php-fpm.sock` зависит от сервера — уточните у хостинга.
